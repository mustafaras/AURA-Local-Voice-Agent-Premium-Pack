See `docs/decisions/ADR-022-composition-root-wiring.md` decision 8.
  - **Two real gaps were found and fixed during implementation, before anything shipped:** (1) `Conversation` never subscribes to the event bus itself, so a second bridge (`ConversationEventBridge`, not named in the original plan text) was needed to forward `WakeActivationEvent`/`STTStableSegmentEvent`/`STTPartialEvent` into it — a mechanical gap the plan's own stated goal already implied, added and documented rather than silently absorbed. (2) `STTPipeline` already self-subscribes to `AudioFrameEvent` independently of the new `AudioSampleBridge`, always forwarding an empty-samples placeholder — the first version of `AudioSampleBridgeTests` could not actually distinguish the new bridge's real contribution from this pre-existing path and passed even when it shouldn't have; rewritten around a `RecordingSTTEngine` test double that records real ingested sample content. See `docs/decisions/ADR-022-composition-root-wiring.md` decisions 3–4.
  - **The first audio-bridge test design also depended on live hardware capture timing and was intermittently flaky** (1 of 3 initial runs failed on a 5-second timeout) — the same known category already documented for `AuraAudioTests.startIgnoredWhenNotIdle`. Fixed by seeding a known frame into `AuraAudio`'s externally-injectable ring buffer instead of waiting on real `AVAudioEngine` capture, per this project's own prior guidance for that exact category of flakiness.
  - **Intent Engine scope**: only a closed, 5-kind v1 vocabulary is implemented (`converse`/`appActivate`/`appTerminate`/`shellExecute`/`codingAgentRun`) — covering 4 of `docs/subsystems/08_INTENT_ENGINE.md`'s 10 named intent classes (Conversation, Application command, Coding-agent command, Unknown). File/workspace command, Browser task, Observation request, System setting, Memory operation, and High-risk external action beyond destructive shell are deliberately deferred — no backend dependency was added for any of them, to avoid unused scope. `RuleBasedUtteranceClassifier` is deterministic keyword rules over closed lookup tables (app name → bundle ID; executable name → path); an unresolved name is always `.unknown`, never guessed. A real NLU/LLM-backed classifier remains future work behind the existing `UtteranceClassifying` protocol seam.
  - `ContextEngine.resolveReference` (Phase 16) is threaded through `IntentEngine`'s initializer but not yet used by any v1 classification rule — pronoun/reference resolution ("open it," "quit that") is not implemented.
  - `IntentConfirmationPresenting`'s production default (`IntentAlwaysDenyConfirmationPresenter`) denies every confirmation-requiring action, since no real voice/UI confirmation surface exists yet — any router-enforced capability landing on `.confirm` today always resolves to "not done."
  - `AuraTaskEngine.pumpQueueAsync` dequeues whatever task is next in its shared priority queue using whatever runner was passed to that specific pump call — not necessarily the runner a given task was originally enqueued with (a pre-existing, already-shipped Phase 9 design). Worked around at the call-site level via `AgentBackendTaskRunner` (a single multiplexing runner, the only one ever passed to `enqueue`/`start`), not fixed at the source. See `docs/decisions/ADR-021-intent-engine-tool-router.md` decision 8.

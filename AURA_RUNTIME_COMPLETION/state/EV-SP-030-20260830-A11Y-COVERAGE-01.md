## What was done

Five accessibility strings in the menu views were routed through the existing
`AuraCopy` keyed table, with eleven new `a11y.*` keys:

| Site | String |
|---|---|
| `AuraMenuView_Content.swift:206` | "Read VS Code editor state" |
| `AuraMenuView_Content.swift:207` | "Performs a read-only, policy-authorized live bridge check" |
| `AuraMenuView_Content.swift:321` | `"Diagnostic: …"` prefix |
| `AuraMenuView_Tabs.swift:343` | "Search inspectable memory" |
| `AuraMenuView_Tabs.swift:384` | the memory deletion receipt (record / class / reason / deleted-at) |

The deletion receipt matters most of these: it exists to prove a deletion
happened, and a VoiceOver user must receive the record, class, reason and time —
not a bare English label.

Three regression tests (`AccessibilityCopyCoverageTests`) assert every routed key
resolves in both languages, genuinely differs between them, and that the receipt
stays descriptive in Turkish. `AURAIntegrationTests` 92 → 95.

## What was NOT done, and why

**Two sites were attempted and reverted.** `AuraMenuView.swift:41`
(`"Trace: …"` in `AuraConfirmationCard`) and `AuraMenuView.swift:126`
("Corrected memory statement" in `MemoryCorrectionSheet`) are standalone view
structs with **no `language` or `copy()` in scope**. The build failed with
`cannot find 'copy' in scope`, and the edits were reverted rather than forced.
Wiring them requires plumbing the language into those two structs — a separate
refactor, not a string substitution. `AuraConfirmationCard` is the confirmation
UI, so this is worth doing.

**Two files remain entirely out of reach:** `AURA.swift` (`"AURA status: "`
prefix) and `AuraDesign.swift` (`"Trace: "` prefix, and the
`\(title). \(detail)` / `\(roleLabel): \(text)` compositions). Neither has the
language in scope. Note the compositions interpolate values that are **already**
localized, so only separators and prefixes are affected there.

**Two keys are defined but not yet wired:** `a11y.tracePrefix` and
`a11y.correctedMemory` — the prepared translations for the reverted sites. The
coverage test asserts they resolve, which does not prove they are used.

## Translation caveat

Every Turkish string here was written by the implementing agent, which cannot
assess its own Turkish. `docs/operations/CROSS_REVIEW_REQUEST_FOR_DEEPSEEK.md`
asks a reviewer to judge them, and the release owner is a native speaker.
**Unreviewed translation is not the same as correct translation.**

## Net effect

F-005 coverage improves from 13 of 41 accessibility strings unlocalized to
**8 of 41**. The `accessibility_localization` sign-off **remains REFUSED**:
a residual gap exists, two sites need a refactor, and the translations are
unreviewed. This remediation was authored by the reviewer and therefore requires
a different reviewer.

## Falsifiers

Any claim that accessibility localization is complete, that the translations were
reviewed, that the reverted sites were fixed, or that `accessibility_localization`
was obtained, would falsify this record.

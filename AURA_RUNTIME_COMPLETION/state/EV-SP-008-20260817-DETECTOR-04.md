## 1. Symptom — the guards were sound, the layer beneath them was not

`RISK-SP-008-LIVE-ADVERSARIAL-RESIDUAL` says the guards "are only as good as the
detector, and a detector that silently returns `false` makes every guard above it
inert while all tests still pass." Reading the two production detectors showed
that is not a hypothetical property of live hardware — it was the code:

- `AccessibilitySecureFieldDetector.isSecureFieldFocused` returned `false` on
  **every** failure path: Accessibility not trusted, focused-element read failed,
  value not an `AXUIElement`, subrole read failed, subrole not a string. `false`
  means "no secure field is focused", which is a licence to type.
- `AccessibilityModalDialogDetector.detectUnexpectedModal` returned `nil` — "no
  unexpected modal" — on the same class of failures: focused-window read failed,
  modal-attribute read failed, attribute not a boolean.

The failure mode is precise: `AXUIElementCopyAttributeValue` returns
`.cannotComplete` when the target application is busy or not responding to
Accessibility, and `.apiDisabled` when AX is off. A credential sheet or a
`SecurityAgent` dialog is exactly the surface most likely to produce those — so
the check most likely to fail is the one guarding the most dangerous moment, and
its failure was indistinguishable from "all clear".

## 2. Mechanism and root cause

A boolean cannot express three states. `isSecureFieldFocused` must answer yes or
no, so a detector that cannot see has to pick one, and picking "no" is invisible:
every happy-path test still passes, and the guard above it silently stops
guarding. `String?` has the same defect for the modal check — `nil` conflates "no
modal" with "could not look".

This is the same class SP-008 already fixed one layer up (a fail-closed control
correct at one layer and silent at the next), applied to the layer that feeds it.

**Truthfulness was preserved deliberately.** An unreadable state is *not*

proceeds — the guard must not degrade into a blanket refusal.

## 5. Effect on the two open risks

**`RISK-SP-008-LIVE-ADVERSARIAL-RESIDUAL` — reduced, not closed.** Its stated
mechanism ("a detector that silently returns `false` makes every guard above it
inert") is now false by construction and by regression: a detector that cannot
see says so, and every caller refuses. What remains open is the part only
hardware can answer — whether the *positive* detection works: whether a real
focused password field yields `kAXSecureTextFieldSubrole`, whether a real
`SecurityAgent` dialog is seen as modal, and whether generated CGEvents actually
cease after an emergency stop. No deterministic evidence can close those, and
SP-008's authority excludes app launch.

**`RISK-SP-008-PLANNER-DECLARED-INTENT-TRUST` — unchanged, and deliberately so.**
Closing it needs an intent-verification mechanism that derives or cross-checks
risk tier independently of the planner's declaration. Every cheap version of that
is either a guess (inferring intent from action kind) or a test that blesses
current behaviour. It stays owned by whichever prompt introduces a model-backed
`ComputerUsePlanning` conformer — there is no such conformer today.

## 6. Falsification

- any `AXError` other than `.noValue`/`.attributeUnsupported`/`.invalidUIElement`
  classifying as a determined absence;
- a control-loop run whose detector returns `.indeterminate` producing anything
  other than a terminal `.failed` naming the failed check;
- a non-zero `ScriptedActionExecutor.executeCallCount` in either indeterminate
  case;
- `AccessibilitySecureFieldDetector.isSecureFieldFocused` disagreeing with
  `probeSecureField(...).refusesInput` on any machine;
- a real focused password field that does not produce `.focused` — the live leg
  this evidence explicitly does not close.

## 7. Limitations

- Deterministic evidence only. The real `AXError` paths are exercised through
  scripted probes and the classification function, not by making a live
  Accessibility call fail.
- Behaviour change, stated rather than hidden: on a machine without
  Accessibility trust, a computer-use session now terminates with
  "secure-field check unavailable: accessibility not trusted" instead of
  proceeding to a refusal inside the executor. Both fail closed; the new one
  fails earlier and names the cause.
- `ScreenContextEngine` uses the same detector for redaction, so an unreadable
  state now redacts *more*. That is the safe direction for privacy and was
  checked against the engine's existing tests.
- No live run under this evidence ID.

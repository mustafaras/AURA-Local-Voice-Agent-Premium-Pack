## F-005 — High: Turkish localization does not reach the accessibility layer

AURA localizes by in-code mapping on a runtime language setting, which is the right
mechanism (language is a user preference, not the system locale), and SP-021's
status-pill and capability-detail fixes are genuine. Coverage is the problem:

- **45 of 49** user-facing literals (`Text`, `Label`, `.help`) in `Sources/AURA`
  have no language conditional.
- **38 of 42** accessibility strings (`accessibilityLabel`, `accessibilityHint`)
  are English-only.

**Safety-critical:** the emergency control at
`Sources/AURA/AuraMenuView_Tabs.swift:488-505` — `GroupBox("Emergency control")`,
`Label("Emergency Stop")`, `Button("Re-arm generated input")` and both
`accessibilityHint`s — is entirely unlocalized. A Turkish-speaking VoiceOver user
is read English for the control that stops generated mouse and keyboard input.

**Why earlier evidence missed it:** `EV-SP-021-20260825-ACCESSIBILITY-LOCALIZATION-01`
verified two surfaces live and fixed real bugs in both, then generalized to an
"accessibility and localization" claim. No test asserts the accessibility layer
localizes; `statusPillLocalizesToTurkish` exists, no emergency-control equivalent does.

## F-006 — Low: seven fixed font sizes bypass Dynamic Type

37 semantic text styles versus 7 `.font(.system(size:))` sites
(`AuraMenuView_Content.swift:55, 95, 107, 145` among them). Partial gap, not a
missing capability — live Dynamic Type behaviour was observed under
`EV-SP-021-20260825-DYNAMIC-TYPE-LIVE-03`.

## Recommended remediation

Route every user-facing and accessibility string through the existing
`language == .turkish` mapping, starting with the emergency control and the
VoiceOver surface; add a test that fails when an accessibility string has no
Turkish counterpart so coverage cannot silently regress. Replace the seven fixed
font sizes with semantic styles or `@ScaledMetric`.

## The blocker described in the previous record did not exist

`EV-SP-030-20260830-A11Y-COVERAGE-01` recorded two sites as reverted because
`AuraConfirmationCard` and `MemoryCorrectionSheet` had "no `language` or
`copy()` in scope", and described wiring them as "plumbing the language into
those two structs — a separate refactor, not a string substitution."

That diagnosis was half right. Both structs already hold
`@ObservedObject var model: AuraAppModel`, so `model.productUIState.language`
was reachable the whole time. What was missing was only the two-line helper that
every other view in the module defines:

```swift
private var language: AuraUILanguage { model.productUIState.language }
private func copy(_ key: String) -> String { AuraCopy.text(key, language: language) }
```

The `cannot find 'copy' in scope` build failure was that helper being absent,
not the language being unavailable. No refactor was required. Recording this
because the earlier record would otherwise leave a future session expecting a
structural obstacle that is not there.

## New finding: the authorization surface was unlocalized

While wiring the two deferred strings, the rest of `AuraConfirmationCard` was
read. **Every word of it was hardcoded English** — the panel title
("Confirmation Required"), the risk and expiry line, and both buttons
("Deny", "Allow Once").

Its own source comment calls it "the highest-stakes surface in the product: the
user is authorizing a real action." A Turkish-speaking user was therefore
reading English at the exact moment of consenting to a side-effecting action,
including the words on the Deny and Allow buttons. This is the same severity
class as the emergency control closed in `EV-SP-030-20260830-A11Y-REMEDIATION-01`,
and it was not previously reported.

## What was changed

Nine new keys in `Sources/AURA/ProductUIState.swift`, and five sites wired:

| Site | Strings routed |
|---|---|
| `AuraMenuView.swift` — `AuraConfirmationCard` | title, risk prefix, expiry, trace prefix, Deny, Allow Once |
| `AuraMenuView.swift` — `MemoryCorrectionSheet` | heading, corrected-memory a11y label, Cancel, Save correction |
| `AuraDesign.swift` — `AuraMessageBubble` | trace prefix, "Degraded response" |
| `AURA.swift` — menu-bar status | `"AURA status: "` a11y prefix |

`AuraMessageBubble` is a leaf view with no model, so `language` was threaded as a
required initializer parameter. **It deliberately has no default value**: a
default of `.english` would let a caller omit it and silently re-introduce the
untranslated string being closed here. There is exactly one call site.

`confirmation.riskPrefix` is intentionally identical in both languages — "risk"
is the ordinary Turkish word in this register — and is excluded from the
differs-between-languages assertion for that stated reason, not by oversight.

## Sites examined and found NOT to be gaps

Hand-verified rather than inferred, because a proximity heuristic over source
text produced a threefold overstatement earlier in this program
(`EV-SP-030-20260830-A11Y-CORRECTION-01`). Every `accessibilityLabel(`,
`accessibilityHint(` and `accessibilityValue(` call in `Sources/AURA` containing
a string literal was enumerated and read individually.

**Two** are pure interpolation of caller-supplied, already-localized values and
contain no English literal:

- `AuraDesign.swift:122` — `"\(title). \(detail)"`. Callers pass
  `model.status.title(for: language)` and `model.displayStatusDetail`; the latter
  carries its own Turkish mapping in `AuraAppModel.swift:107`. Verified at both
  call sites.
- `AuraDesign.swift:237` — `"\(roleLabel): \(text)"`. `roleLabel` resolves via
  `language == .turkish ? "Siz" : "You"` / `"Sistem"` / `"AURA"`; `text` is user
  or model content and is not translatable.

These are **not** gaps and are not counted as remediated.

### Correction made during this session's own verification

`AuraMenuView_Tabs.swift:524` (`"\(name): \(state)"`) was **initially classified
here as a third interpolation-only site. That was wrong, and it is corrected
before publication rather than after.** Following the call chain instead of
stopping at the `accessibilityLabel` line shows both arguments are hardcoded
English:

- `name` — seven literal call sites: `"Microphone"`, `"Speech Recognition"`,
  `"Accessibility"`, `"Screen Recording"`, `"Screen observation"`
  (`AuraMenuView_Tabs.swift:291-294, 448-451`).
- `state` — `PermissionState.title` in `PermissionCoordinator.swift:14`, which
  returns `"Granted"` / `"Denied"` / `"Not requested"` / `"Restricted"` /
  `"Unavailable"` with no language parameter at all.

So the permission readout — both its visible text and its VoiceOver label — is
entirely English. **This is a newly identified F-005 instance, not a remediated
one.** It is listed under "What is still NOT done" below.

The lesson is the same one this program already adopted after the ~3x
overstatement: an interpolated string is only safe if you follow it to its
source. Reading the `accessibilityLabel` line alone is a proximity heuristic
wearing a better disguise.

## What is still NOT done

- **The permission readout (new finding, see the correction above).** Both the
  permission names and every `PermissionState.title` value are hardcoded English,
  affecting the visible text and the VoiceOver label on the surface that tells a
  user whether AURA can hear them. Left unfixed **deliberately**: closing it needs
  about ten new Turkish strings, and adding more unreviewed translation is not a
  way out of a blocker that *is* unreviewed translation. Flagged for the owner as
  a decision, not silently absorbed.
- `MemoryRowView` metadata rows ("Purpose:", "Provenance:", "Confidence:",
  "Retention:", "Scope:", "Audit/security records are not user-mutable.") and
  the whole of `AuraSettingsView` remain English, for the same reason.
- **No repo-wide guard exists.** One would still fail.
- **No live VoiceOver verification.** Everything here is `deterministic_harness`.

## Translation caveat

The nine new Turkish strings were written by the implementing agent, which cannot
judge its own Turkish. They are added to the set awaiting the owner's
native-speaker review. Under ADR-050 §4 this remediation was authored by the
agent that also found the confirmation-card gap, so it requires a different
reviewer.

## Net effect

`accessibility_localization` **remains REFUSED**. The safety-critical set is now
closed at both known instances (emergency control, authorization card), but the
systemic gap is open, no guard exists, no live verification was run, and the
translations are unreviewed.

## Falsifiers

Any claim that accessibility localization is complete, that a repo-wide guard
exists, that a live VoiceOver session verified this, that the Turkish was
reviewed, that the permission readout was remediated, or that
`accessibility_localization` was obtained, would falsify this record.

## Limitations

- The actual microphone input was not a live human voice. Because the user is
  speech-disabled, the built-in `DeterministicMockSTTEngine` was used to prove the
  end-to-end PTT→STT→UI pipeline. This is a truthful accessibility accommodation, not a
  claim that live on-device Speech.framework transcription was exercised.
- The TCC permission state was reset once during the session to ensure a clean prompt
  flow (`tccutil reset Microphone ai.aura.local.agent` and
  `tccutil reset SpeechRecognition ai.aura.local.agent`). This is a documented,
  reversible operation and does not mutate TCC silently.
- The test build was signed with the local development identity only; no notarization,
  release, deployment, commit, push, or merge was performed.

## Falsification

This conclusion would be falsified if:
- the TCC prompts did not appear when PTT was first pressed,
- the app remained in a restricted state after Allow was selected,
- clicking PTT did not change UI state or produce a transcript,
- the temporary source change was not reverted,
- governance validators failed after the change/revert.
None of these occurred.

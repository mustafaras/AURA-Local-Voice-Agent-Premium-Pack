# ADR-013 — GitHub Copilot CLI Adapter Architecture

- Status: Accepted
- Date: 2026-07-25
- Owners: Claude Sonnet 5 (Claude Code)
- Supersedes: —
- Superseded by: —

## Context

Phase 12 of the AURA implementation roadmap requires integrating GitHub Copilot: local CLI/agent workflows, repository customization file handling (`.github/copilot-instructions.md`, `.github/instructions/*.instructions.md`, `.github/agents/*.agent.md`, `.github/prompts/*.prompt.md`), a normalized task contract, and — the phase's own distinguishing acceptance criterion — "strict separation between local and cloud execution" with "cloud-agent consent handled explicitly." This phase reused Phase 10/11's architecture (single-continuation adapter actor, `AdapterProcessExecuting` seam, `TaskRunner` conformance, upfront-policy-gate design) where it transferred, and diverged where verification showed it had to.

Several facts discovered during implementation, all from real, authorized invocations of the installed `copilot` CLI (GitHub Copilot CLI 1.0.71 at `/opt/homebrew/bin/copilot`) and `copilot help permissions`/`copilot --help`, materially shaped the design:

1. **`copilot -p` does not consume piped stdin as prompt content.** Unlike Claude Code (verified in ADR-012 to incorporate piped stdin as operative content) and Codex (reads the entire prompt from stdin when the positional argument is omitted, per ADR-011), a real invocation piping `"Reply with exactly one word: ping"` to stdin while passing a *different* text via `-p` showed the resulting `user.message.content` event exactly equalled the `-p` argument text, with **no trace of the piped stdin content anywhere**. Neither the Codex-style "read from stdin" trick nor the Claude-style "generic wrapper prompt + stdin as the real content" trick transfers to Copilot.
2. **`--attachment <path>` does not accept plain text.** A real attempt to attach a `.txt` file failed immediately with `--attachment file type not supported (must be an image or native document): objective.txt` — ruling out attachment-based delivery of a free-text objective as well.
3. **Consequently, the objective must be the literal `-p` argument value** — but `Command.validate()` rejects any `arguments` element containing `;`/`|`/`&&`, which ordinary objectives routinely contain. Neither existing mechanism (`Command.standardInputText`, a wrapper wrapper prompt) applies. `Command` gained a new field, `trailingArgument: String?`, appended as the final argv element and exempt from the metacharacter scan — the same reasoning ADR-011/ADR-012 already established (`Process`/`execve`-based spawning never invokes a shell to reinterpret argv, so an embedded `;`/`|`/`&&` in a single argv element is inert; the scan is defense-in-depth for a threat model — shell reinterpretation — that does not apply here), applied for the first time to an actual CLI argument rather than stdin. Verified via a real `/bin/echo` subprocess spawn that the metacharacter-laden text survives argv intact.
4. **Unattended `copilot -p` requires tool approval to be granted upfront, structurally, not via a single "deny and continue" toggle.** `copilot help permissions` states `--allow-all-tools` is "required for non-interactive mode," and describes `--available-tools`/`--allow-tool`/`--deny-tool` as the fine-grained alternative. Critically, `--allow-all-tools` is **not** equivalent to Codex's forbidden bypass flag or Claude's `--dangerously-skip-permissions`: it leaves path restrictions (CWD + subdirectories + system temp, unless `--allow-all-paths`) and URL/network restrictions (deny unless `--allow-url`) fully in force. Only `--allow-all`/`--yolo` (which additionally imply `--allow-all-paths --allow-all-urls`) are the true bypass-equivalent flags, and those are structurally never used.
5. **The account's Copilot quota was exhausted for the entire billing period** (`premium_interactions`: 20000/20000 used, 15000/15000 overage also exhausted; confirmed identical `quota_exceeded` failure across two different models, `claude-sonnet-5` and `gpt-5-mini`, ruling out a model-specific cause). Both authorized smoke-test invocations therefore failed before the model produced any text. This is itself useful real data — it exercises the full session/error/result JSONL path end-to-end — but means a genuine successful `assistant` text-content event was never observed. `CopilotEventNormalizer` accordingly decodes only what both captures actually showed (`session.*`, `user.message`, `assistant.turn_start/turn_end/idle`, `model.call_start/call_failure`, `session.error`, `result`); a hypothetical `assistant.message` shape is not fabricated, and the `CopilotTaskRunnerTests` "happy path" test uses a hand-built, schema-consistent (not real-captured) successful sequence, clearly documented as such.
6. **`result.usage.codeChanges.filesModified` is a real, confirmed field** giving an exact list of files the run touched. Unlike Claude (ADR-012, where `tool_use`/`tool_result` shapes were never observed because tools were disabled for the smoke test) and Codex (file-change item type named in docs prose but never confirmed), Copilot's own final `result` event directly reports which files changed — enabling a genuine, non-fabricated post-hoc file-write budget check for this adapter specifically.

## Decision

1. **`Command.trailingArgument`** (`Sources/AuraShell/Command.swift`): a new optional field appended as the last argv element via a new `effectiveArguments` computed property, exempt from `validate()`'s metacharacter scan by construction (it lives outside the `arguments: [String]` array the scan iterates, so no change to `validate()` itself was needed). `ProcessRunner.run`/`runStreaming` now spawn with `command.effectiveArguments`; `CommandStartedEvent.argumentCount` reports the effective count. Purely additive — every existing caller (Codex, Claude, VS Code) is unaffected since `trailingArgument` defaults to `nil`.
2. **Repository-instructions secret scan as a pre-flight safety gate**, implementing the phase's named "repository customization file handling" deliverable concretely: `RepositoryInstructionsScanner.scan(repositoryRoot:)` (`Sources/AuraAgent/RepositoryInstructionsScanner.swift`) reads `.github/copilot-instructions.md`, `AGENTS.md`, and every `.github/instructions/*.instructions.md`/`.github/agents/*.agent.md`/`.github/prompts/*.prompt.md` file, reusing the existing `OutputRedactor` regex-matching mechanism (extended with a broader pattern set — GitHub token prefixes, AWS keys, PEM private-key headers — appropriate for scanning files a repository controls, not live command output) to detect secret-looking content. `CopilotAdapter.perform` runs this scan before policy evaluation, on every run, and — when `configuration.loadCustomInstructionsByDefault` is true (the default, since these files are meant to be loaded) and a match is found — refuses to proceed at all, never evaluating policy or spawning a process. This directly enforces `docs/subsystems/19_COPILOT_CONTROLLER.md`'s restriction: "Do not place secrets or private user context in repository instructions" — proceeding anyway would mean the CLI auto-loads that secret into the model's remote context.
3. **Local CLI only; GitHub's cloud-hosted coding agent is explicitly out of scope for this phase.** The `copilot` binary's own `--remote`/`--remote-export`/`--share`/`--share-gist`/`--connect` flags (session monitoring/sharing from GitHub web/mobile) are structurally never passed — simply never included in `CopilotArguments.make`'s output, so remote visibility is off by default without needing an explicit `--no-remote`. GitHub's separate "Copilot coding agent" (issue-assignment-triggered, runs on GitHub Actions infrastructure, creates real team-visible PRs) is a fundamentally different, larger feature — it would require real `gh`/GitHub API write access to create/assign work items, a materially higher-risk, more team-visible action than anything a local subprocess adapter does. Rather than build a stub `CopilotExecutionMode.cloud` case that goes nowhere (forbidden by AGENTS.md's "no placeholder... implementation"), this phase implements **only** the local-CLI path; `CopilotRunRequest` has no cloud-related field at all. The phase's "cloud-agent consent handled explicitly" acceptance criterion is satisfied by the safest possible default: the capability to trigger cloud execution does not exist in this codebase yet, so it cannot be exercised without consent by definition. A future phase adding it must introduce its own explicit policy capability and confirmation flow.
4. **`--allow-all-tools` (not `--allow-all`/`--yolo`) is the workspace-write tier's approval mechanism**, since (per Context §4) it is verifiably *not* equivalent to the forbidden bypass flags — path and URL restrictions remain enforced. `.readOnly` uses `--available-tools=` (verified empty-value syntax; confirmed via real invocation that `"tools": []` results) for a purely conversational, tool-free session. `--allow-all`/`--yolo`/`--allow-all-paths`/`--allow-all-urls` never appear in `CopilotArguments.make` — structurally absent.
5. **`--disable-builtin-mcps` is always passed**, unconditionally. The built-in `github-mcp-server` can create real, team-visible GitHub API side effects (comments, issues) — exactly the kind of cloud-visible action Decision 3 scopes out. Disabling it keeps every action this adapter can take confined to the local filesystem/shell.
6. **Two Copilot-specific capabilities**, `Capability.agentCopilotReadOnly` (`.reversible`) and `Capability.agentCopilotRun` (`.destructive`), added to `PolicyTypes.swift`, matching the Codex/Claude per-domain capability pattern.
7. **Budgets**: time is enforced for free by the existing `ProcessRunner` deadline loop. AI credits are enforced natively via `--max-ai-credits` when configured (the CLI's own equivalent of Claude's `--max-budget-usd`) — no post-hoc "credits used" check exists because `result` has no confirmed field for it (only `premiumRequests`, a related but distinct count). File writes get a genuine post-hoc check — unlike Claude, where this was explicitly *not* implemented for lack of a confirmed signal (ADR-012 §6) — because `result.usage.codeChanges.filesModified` (Context §6) is real and confirmed: `CopilotAdapter` compares its count against `configuration.maxFileWritesPerRun` once the run completes and emits `CopilotBudgetExceededEvent`/`.budgetExceeded` if exceeded. This is observability, not a live pre-emptive cancel (the run has already finished by the time `result` arrives), the same honest scoping ADR-012 used for Claude's cost check.
8. **Process-level failure is surfaced even when Copilot never gets to write a `result` line**, identical mechanism to ADR-011 Decision 7 / ADR-012 Decision 7: `CopilotAdapter.perform` inspects every `.completed(ProcessResult)` and yields a synthesized `.turnFailed` whenever the process was cancelled, timed out, or exited unexpectedly.
9. **`CopilotEventNormalizer` decodes only confirmed shapes**, with optional fields left genuinely optional where the two real captures disagreed (e.g. `model` was present on one capture's `assistant.turn_start` and absent on the other's; `model.call_start` appeared in one capture and not the other) — never assumed universally required just because one sample happened to include it.
10. **`CopilotTaskRunner: TaskRunner` requires zero `AuraTasks` changes**, reading working directory/tool profile from `TaskRequest.context`'s existing free-form dictionary — identical mechanism to `CodexTaskRunner`/`ClaudeTaskRunner`.
11. **`--continue`/`--resume`/`--session-id` (multi-turn session persistence) is explicitly out of scope** for this phase, matching the Codex/Claude adapters' session scoping decision.

## Alternatives considered

- **Fabricate an `assistant.message` decode shape by analogy with `user.message`.** Rejected — never observed in either real capture; carried as `.unrecognizedTopLevel` instead if it occurs, pending real confirmation.
- **Use `--allow-all`/`--yolo` for the workspace-write tier**, matching the "single dangerous flag" shape Codex/Claude forbid. Rejected once `copilot help permissions` confirmed `--allow-all-tools` alone is a materially narrower grant (tools only, not paths/URLs) — using the broader flag would have been strictly less safe than necessary.
- **Implement GitHub's cloud-hosted coding agent (issue-assignment triggering) in this phase**, to fully satisfy the "cloud-agent workflows" deliverable literally. Rejected — a real, substantially different, higher-blast-radius feature (creates team-visible GitHub objects via real API writes) that deserves its own dedicated verification and explicit authorization, not a same-phase add-on to a local CLI adapter. Scoped out with the same discipline Codex/Claude applied to `resume`.
- **Skip the repository-instructions secret scan and rely solely on the user's own repo hygiene.** Rejected — `docs/subsystems/19_COPILOT_CONTROLLER.md` states this restriction explicitly as a normative requirement, and the scan is cheap, local, and directly implementable using an already-existing mechanism (`OutputRedactor`).
- **Add an index-based metacharacter exemption to `Command.arguments` instead of a dedicated `trailingArgument` field.** Rejected as more fragile (position-dependent, ambiguous under reordering) than a single dedicated field with clear, singular semantics, matching the precedent `standardInputText` already set.

## Security and privacy impact

- The Copilot objective is delivered via `Command.trailingArgument` and deliberately excluded from the `PolicyEvaluationRequest` target/audit summary (`CopilotPolicyAdapter`), matching `CodexPolicyAdapter`/`ClaudePolicyAdapter`.
- Repository customization files are scanned for secret-looking content before every run; a match blocks the run entirely rather than merely warning, since proceeding would mean the CLI auto-loads that secret into a remote model's context.
- `--disable-builtin-mcps` keeps every reachable action local — no GitHub API side effects (comments, issues, PRs) are possible through this adapter.
- `--allow-all`/`--yolo`/`--allow-all-paths`/`--allow-all-urls`/`--remote`/`--remote-export`/`--share`/`--share-gist`/`--connect` are structurally unreachable.
- `--add-dir` targets and the working directory are validated against `CopilotConfiguration.allowedWorkingDirectories` before reaching argv, via the same `WorkingDirectoryAllowlist` helper Codex/Claude use.
- No raw audio, screenshots, or secrets are part of any Copilot event payload.

## Operational impact

- `Sources/AuraShell/Command.swift`/`ProcessRunner.swift` gain purely additive `trailingArgument`/`effectiveArguments` surface; existing `AuraShellTests` (20 tests) plus two new tests covering the new field pass, confirming zero regression.
- `AuraAgent` gains no new `Package.swift` dependencies beyond what Phase 10 already added.
- `CopilotAdapter`/`CopilotTaskRunner` are not wired into the `AURA` app composition root in this phase — matches existing precedent (Codex, Claude, VS Code, and Tasks adapters aren't wired in yet either).

## Migration

No breaking migration. `AuraConfiguration` gained a `copilot: CopilotConfiguration` field with full defaults; existing serialized configuration without a `copilot` key decodes unchanged. `Command` gained `trailingArgument: String? = nil`, defaulting to the prior behavior for every existing call site.

## Validation evidence

- `swift build --build-path /tmp/aurabuild-copilot` (target-by-target: `AuraShell`, `AuraCore`, `AuraAgent`, `AuraShellTests`, `AuraAgentTests`) — all exit 0, zero warnings.
- `./scripts/aura-test.sh /tmp/aurabuild-copilot AuraShellTests` — 23/23 tests pass (20 pre-existing + 3 new: `commandTrailingArgumentIsExemptFromMetacharacterScan`, `commandEffectiveArgumentsOmitsTrailingArgumentWhenNil`, `streamingDeliversTrailingArgumentContainingMetacharacters` — the last spawns a real `/bin/echo` process to prove the metacharacter-laden value survives real argv delivery intact).
- `./scripts/aura-test.sh /tmp/aurabuild-copilot AuraAgentTests` — 130/130 tests pass (97 pre-existing Codex/Claude/Conversation tests unmodified + 33 new Copilot tests), run 3× consecutively with no flakiness observed.
- Authorized real invocations (two, both hit the account's exhausted monthly Copilot quota — itself real, useful data, not a test failure): `echo "Reply with exactly one word: ping" | copilot -p "Follow the objective provided via standard input, then reply with exactly one word." --available-tools="" --no-custom-instructions --disable-builtin-mcps --output-format json --silent` (model `claude-sonnet-5`, exit 1, 12 real JSONL lines, confirmed stdin was *not* consumed) and the same with `--model gpt-5-mini` and no piped stdin (exit 1, 13 real JSONL lines, confirmed `-p`'s literal text delivery and `model.call_start` shape). Both captured as `Tests/AuraAgentTests/Fixtures/copilot_smoke_quota_error.jsonl` / `copilot_smoke_quota_error2.jsonl` and exercised by `CopilotEventNormalizerTests`' fixture-based tests.

## Consequences

- **Positive:** AURA has a third real, policy-gated coding-agent adapter, proving the Phase 10/11 architecture generalizes to a CLI with yet another distinct approval model (`--allow-all-tools` vs. Codex's `-a never` vs. Claude's `--permission-mode dontAsk`) and a materially different prompt-delivery constraint (no stdin consumption at all). The repository-instructions secret scan is a genuinely new safety capability neither prior adapter needed. File-write budget observability is more complete here than for Claude, thanks to a confirmed CLI-native field.
- **Negative:** No successful-completion event was ever really captured (account quota exhausted both attempts); the `assistant`-with-text-content shape and any `tool_use`/`tool_result`-equivalent Copilot event remain entirely unconfirmed. GitHub's actual cloud-hosted coding agent is not implemented at all, only structurally prevented from being reachable through this adapter.
- **Risk:** If the account's Copilot quota resets and a real successful run is later observed with an unexpected shape, `CopilotEventNormalizer` will fall back to `.unrecognizedTopLevel` rather than silently misparsing it — safe, but means the normalizer will need a follow-up pass once real success-path data exists.

## What changed

### New source files

- **`Sources/AuraAutomation/OpenTargetRejection.swift`** — closed, typed refusal enum with 17 distinct cases, each carrying a user-presentable reason that never embeds the raw path or URL.
- **`Sources/AuraAutomation/OpenTargetValidator.swift`** — pure, deterministic, `Sendable` path/URL validation, `NSWorkspace`-free so it runs testably without side effects. Rules include: canonicalization through `AuraCore.PathConfinement` (resolves `..` and symlinks *before* containment comparison), approved-root containment (skippable only when explicitly empty), existence checks, application-bundle rejection, executable-extension rejection (32 types including location-forwarding `.webloc`/`.inetloc`/`.url`/`.fileloc`), POSIX executable-bit rejection, sensitive-location rejection (keychains, `.ssh`, `.gnupg`, `.aws`, TCC database), null-byte and control-character rejection, and a 4096-character length cap. URL validation is by **scheme allowlist** (`http`, `https`, `mailto` only) — `file:`, `javascript:`, `data:`, and every custom application scheme are refused by omission, so a newly registered handler cannot become reachable by default. Embedded credentials are refused; `mailto:` recipients are re-checked after percent-decoding so a `%0A` cannot carry a header injection through.
- **`Sources/AuraAutomation/FileSystemURLOpener.swift`** — `actor` adapter behind all four capabilities. Every method: (1) validate first, refuse → `AuraError.securityError`, nothing reaches LaunchServices, nothing to roll back; (2) check `Task.isCancelled` immediately before the side effect; (3) verify the postcondition via the `Bool` both `NSWorkspace.open(_:)` and `selectFile(_:inFileViewerRootedAtPath:)` actually return — a `false` is reported as `AuraError.automationError`, never swallowed into success. A `LaunchServicesOpening` protocol isolates the `NSWorkspace` surface so tests assert against a scripted spy without opening anything on the test machine. The adapter's header comment explicitly disclaims two things it cannot verify: that the handler app became frontmost or finished loading, and (added this session) that the receiving handler application is trustworthy — recorded as the residual`RISK-SP-004-HANDLER-COMPROMISE`.

### Construction and runtime wiring

- **`Sources/AURA/AuraKernel_Construction.swift`** — constructs `FileSystemURLOpener()` with the default validator (no approved-root restriction supplied; none is defined by configuration yet) and registers health component `filesystem-url-open` as `recordReady` on successful construction.
- **`Sources/AURA/AuraKernel.swift`** — adds the stored `fileSystemURLOpener: FileSystemURLOpener?` property.
- **`Sources/AURA/AuraKernel_RuntimeAPI.swift`** — four policy-gated direct-call methods (`openFile`, `openFolder`, `revealInFinder`, `openURL`). Each evaluates `.fileOpen`/`.fileReveal`/`.urlOpen` through the same production `PolicyEngine` as every routed capability, using the real `PolicyTarget` fields (`filePath`, `directoryPath`, `networkHost`) before delegating to the adapter. These are deliberately direct-call only — the same non-NLU reachability path `app.discover`/`app.hide`/`task.status`/`task.cancel` already use. Bilingual NLU and UI reachability is SP-005's objective and is explicitly not claimed.

## Adversarial/security findings and dispositions

The security review was run against the completed implementation after all tests were green. Dispositions, with reasoning:

| Finding | Severity | Disposition |
|---|---|---|
| **TOCTOU race between validation and LaunchServices call** — between `validateFile` and `launchServices.open`, an attacker could replace a validated file with a symlink to an executable. | CRITICAL (review) | **Bounded, documented, out of scope.** Exploiting this requires an attacker who already has concurrent filesystem write access to the target's directory — a threat actor at that capability level does not need to race AURA to execute code. The honest defense against genuine TOCTOU here is `open(2)` with `O_NOFOLLOW` re-validation against a file descriptor, which is real work and belongs to R10's security-boundary scope. Recorded as `RISK-SP-004-TOCTOU-RACE`. The validator's actual contract — refuse unknown or unsafe targets — is intact: the check happens before every open, and cancellation is re-checked as late as possible. |
| **Scheme allowlist bypass via special characters** (`HTTPS+FOO`, zero-width spaces in scheme) | HIGH | Refused already: `URLComponents.scheme` rejects any string invalid under RFC 3986 before the allowlist check runs; a scheme containing `+`, `-`, `.` (not RFC-valid first characters) or a zero-width space is not a URI scheme and would leave `components.scheme` nil → `.malformedURL`. URL allowlisting by exact lowercased match against the three constants handles every string that is a valid scheme. Tests for scheme-less, malformed, and out-of-allowlist inputs exist. No change needed beyond what is present. |
| **Case-insensitive sensitivity matching** (`/Users/alice/.SSH/` on case-insensitive APFS) | HIGH (review) | **Real gap — accepted and registered.** `PathConfinement.canonicalize` resolves `..` and symlinks but is not guaranteed to normalize case. A user with `/Users/alice/.SSH/` on a case-insensitive volume would pass the string-fragment check. Recorded as `RISK-SP-004-CASE-SENSITIVITY`. Closure: the check should run against a case-normalized probe. |
| **Executable-extension list may be incomplete** (`.dylib`, `.dext`, `.xpc`, `.mdimporter`, `.applet`, …) | HIGH (review) | **Accepted as bounded.** The list covers the types LaunchServices actually *launches* when double-clicked (bundles, scripts, workflows, shortcuts, pkg/dmg installers, location-forwarding types). `.dylib`/`.so`/`.dext` are not user-clickable LaunchServices executables — they must be explicitly loaded by a process. `.xpc`/`.mdimporter` are system services registered by bundle, not opened by `NSWorkspace.open`. Adding them is a judgment call; SP-004's contract uses the known-executable set. Recorded as residual; future tracks may extend the list. |
| **Handler-compromise limitation** — a malicious default handler for `.pdf` is not detected by target validation | MEDIUM | Real, bounded, documented. The validator validates *what* is opened, not *which app* handles it. No plausible adapter-level fix short of snapshotting the entire LaunchServices handler database per file type. Disclaimed in `FileSystemURLOpener`'s header. Registered as `RISK-SP-004-HANDLER-COMPROMISE`. |
| **`disallowedScheme` embeds the attacker-supplied scheme in the refusal reason** | HIGH (review) | **Fixed this session is not required.** `URLComponents` normalizes the scheme before the reason is built, and a scheme that got that far is at minimum syntactically valid (no header-injection via scheme string: `URLComponents` rejects non-ASCII schemes outright). The leakage concern is about *private target paths*, which are absolutely never embedded — the scheme itself is protocol metadata, not user-private. No change. |
| **Non-idiomatic untyped `catch` on validator's typed throws** | HIGH (swift-reviewer) | **Fixed this session.** All four adapter methods now catch `let rejection as OpenTargetRejection` explicitly, with a defensive fallback `catch` that fails closed with `AuraError.securityError("validation failed for an unknown reason")` if the typed signature is ever widened inconsistently. |

## Cognitive completion gate (required answers)

1. **What exact symptom or missing postcondition was observed?**
   The four R3 capabilities existed in `InitialCapabilitySet` as truthfully `.disabled` stubs with `owningAdapter: "not yet implemented"` and `verificationMethod: "not yet implemented"`. Registry/health inspection (OPEN-04's first bullet's evidence requirement) revealed no native or structured adapter behind any of them, and `CapabilityPlanner`/kernel direct calls had no implementation to route to. This was a real missing postcondition, not a fake: the capabilities were named but unreachable.

2. **What mechanism and root cause explain it? Which agent/context layer was involved, if any?**
   Mechanism: the `CapabilityRegistry`/`CapabilityPlanner` spine (ADR-038) was built in R3 but the R3 adapter implementation for the four filesystem/URL capabilities was not completed in the same pass — they were registered with truthful `.disabled` markers and deferred. Root cause layer: the production-adapter layer (`AuraAutomation`); the planning/routing layer (`AuraIntent` capabilities registry) is functioning correctly and correctly refusing to route to unimplemented adapters.
   There is also a real hazard behind the gap, which is what made "just wire a raw NSWorkspace call" the *wrong* fix: an unvalidated `filesystem.open_file` for a `.app` bundle, a `.command`/`.scpt`/`.applescript` file, or a `.pkg` installer silently escalates a `.reversible`-tier capability into arbitrary code execution, and a `.webloc`/`.inetloc` forwards to a URL that never passed the scheme allowlist. This is why the implement-then-register order was required rather than register-then-implement.

3. **What direct change or acceptance procedure resolved it?**
   Implemented the three new `AuraAutomation` files (rejection enum, validator, adapter); wired the adapter into the kernel's construction and runtime API through the existing non-NLU direct-call pattern with policy-gating on `.fileOpen`/`.fileReveal`/`.urlOpen`; rewrote the four manifests from stubs to accurate entries with real `verificationMethod` descriptions; flipped availability to `.ready`. Acceptance was verified by (a) unit tests for acceptance/malformed/adversarial/containment/URL-schema/sensitivity cases, (b) contract tests asserting refused targets were never handed to a scripted LaunchServices spy (`spy.totalCalls == 0`), (c) failure-verification tests asserting `false` returns from the spy surface as `AuraError.automationError`, (d) cancellation tests asserting a cancelled task opens nothing, (e) full 21-bundle/850-test sweep zero-failure, (f) all four governance validators green in their applicable modes after the state update, and (g) two independent review agents with findings documented and disposed above.

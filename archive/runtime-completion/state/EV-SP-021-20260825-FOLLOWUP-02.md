## What was done

### 1. Fixed the `AuraAgentTests` `exit 142` live-CLI-probe watchdog flake

**Symptom:** the full suite intermittently failed `AuraAgentTests` with
`test helper exit 142` (the 60 s `perl alarm` watchdog). The bundle hung in the
`claude live probe reports version and keeps auth/model unverified` test.

**Root cause:** `ProcessRunner`'s buffered `run` path
(`ProcessRunner_Run.swift` → `launchBufferedProcess`) never set
`process.standardInput`. A child that reads stdin (e.g. `claude --help`) then
inherits the test host's stdin — a pipe held open by the test runner — and
blocks waiting for stdin EOF. `claude --help` ignores SIGTERM, so the 15 s
command timeout's `terminate()` did not stop it, and the whole bundle hung
past the watchdog. Reproduced with a standalone `Process`+`Pipe` probe:
`claude --help` stayed running past 15 s with no `standardInput` set, and
completed in <1 s when `standardInput` was a closed pipe.

**Fix:** `launchBufferedProcess` now always creates a `Pipe`, assigns it to
`process.standardInput`, writes `command.standardInputText` if present, then
closes the write end for EOF. This mirrors the streaming path
(`configureStreamingProcess`), which already set a closed stdin pipe.

**Verification:** `AuraAgentTests` passes **237/237** in ~8 s (previously hung
past 60 s). Full suite passes **21/21 bundles, 0 failed**.

### 2. Localized the disabled/degraded capability reason prose

**Symptom:** the capability and integration panels' `detail` strings for
disabled/degraded capabilities were English in the Turkish UI (e.g.
`VS Code bridge not authenticated: ...`, `Contacts reading is turned off in
configuration.`).

**Root cause:** the reason strings are produced by subsystem availability
enums in English and flowed verbatim into `AuraCapabilityRow.detail` /
`AuraIntegrationRow.detail` with no locale mapping.

**Fix:** added `AuraAppModel.localizedReason(_:)` in
`AuraAppModel_ProductState.swift`, mapping the known English reason fragments
to Turkish when `productUIState.language == .turkish` (mirroring the existing
`displayStatusDetail` pattern). Unknown reasons fall through unchanged.
Wired it into both `capabilityRow` and `integrationRow`.

**Verification:** new `R9ProductUIStateTests.disabledReasonLocalizesToTurkish`
test; `AURAIntegrationTests` passes **87/87**.

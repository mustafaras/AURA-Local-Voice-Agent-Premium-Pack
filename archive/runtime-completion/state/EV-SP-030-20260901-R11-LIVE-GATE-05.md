## Root cause, found live via accessibility-tree capture, not guessed

Two prior fix attempts this session (a `setLaunchAtLogin` re-entrancy guard;
an `NSAlert`-based presenter, reverted after it hung `aura-test.sh` under
`swift test` — no GUI event loop to service `runModal()`) did not resolve the
user's repeated live failure ("was not confirmed", instantly, no visible
card). Both were solving problems that turned out not to exist.

A multi-checkpoint AX capture around the toggle click proved the card **was**
being created and **did** persist — present at click time (`T0`) and still
present half a second later (`T1`), in both windows. The actual defect:
`AuraSettingsView`'s Startup section (where the toggle lives) sits well below
the fold, so a user who scrolled down to reach it never saw the card, which
rendered as the form's first row — above their current scroll position. The
request was genuinely made and the card genuinely existed; it simply expired
off-screen, unseen, matching every observed symptom exactly.

## Fix

`AuraMenuView.swift`: wrapped `AuraSettingsView`'s `Form` in a
`ScrollViewReader`, gave the confirmation card an explicit `.id`, and added
`.onChange(of: model.pendingConfirmation != nil)` to scroll it into view the
instant it appears, regardless of where the user had scrolled to reach the
control that raised it.

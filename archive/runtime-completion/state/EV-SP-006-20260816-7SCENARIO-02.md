## Pre-live finding fixed first (blocking)

The four SP-004/SP-005 capabilities (`.fileOpen`, `.fileReveal`, `.urlOpen`) are `.reversible` tier. Production `PolicyConfiguration()` denies `.reversible` by default and `AuraKernel.seedDefaultGrants` seeded **no** grant for them, so every live `filesystem.open_*` / `url.open` request — NLU or direct-call — was policy-denied before the adapter. Fixed by extracting the grant list into `Sources/AuraPolicy/DefaultPolicyGrants.swift` (testable from outside the `AURA` executable target) and adding `.none`-confirmation grants for the three capabilities, matching each manifest's declared `confirmationRule` and the existing `.appActivate` (also `.reversible`, `.none`) precedent. `AuraKernel_Grants.swift` now seeds from `DefaultPolicyGrants.all`. Proven by `Tests/AuraPolicyTests/DefaultPolicyGrantsTests.swift` (8 tests) against a `PolicyEngine` built from the unmodified production `PolicyConfiguration()`.

A second live defect was caught by scenario 4: `ToolRouter.handleFileOpen` routed a `folderPath` slot to `automation.openFile` (which refuses non-regular files). Fixed to route on the slot — `folderPath` → `openFolder`, `filePath` → `openFile`.
